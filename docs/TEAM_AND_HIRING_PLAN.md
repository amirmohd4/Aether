# Aether — Team Design and Hiring Sequence

## Operating principle

Aether is a regulated-domain, multi-tenant workflow and execution platform. Do not staff it like a generic chatbot startup. The team must combine platform engineering, administrative process expertise, security and delivery operations.

The founder owns company strategy, customer relationships, capital allocation and final product decisions. AI-assisted engineering can accelerate implementation but does not replace accountable human engineering, legal review, security review or government-domain validation.

## Minimum core team for a credible India-first beta

| Role | Accountability | Hiring priority |
|---|---|---|
| Founder / CEO | Vision, capital, partnerships, customer discovery and decisions | Founder |
| CTO / Principal platform engineer | Architecture, reliability, security, technical standards and code review | Immediate |
| Backend / workflow engineer | Case engine, graph execution, queues, connectors and APIs | Immediate |
| Frontend product engineer | Citizen/business/officer experiences, accessibility and usability | Immediate |
| Government process researcher | Department mapping, service procedures, jurisdiction variants and source evidence | Immediate |
| Government-domain legal / former-administration advisor | Validate statutory interpretation, authority boundaries and procedural reality | Fractional, immediate |
| QA / automation engineer | API, workflow, regression, security and scenario testing | Early |
| Security / privacy specialist | Threat model, data protection, tenant isolation, retention and incident readiness | Fractional, before public beta |
| Integration engineer | Authorized API and portal connectors, sandbox certification and reconciliation | Before live pilots |
| Product designer / researcher | User research, interaction design and usability testing | Fractional / early |

## Hiring sequence

1. Appoint a hands-on CTO / principal engineer who can own production quality.
2. Recruit one backend/workflow engineer and one frontend engineer.
3. Engage a government process researcher and a qualified legal/administrative advisor on a paid, documented basis.
4. Engage security/privacy and QA specialists before public beta.
5. Add integration engineers only as specific authorities provide approved sandbox access and credentials.

## Government advisor safeguards

- Prefer former officers or independent domain experts with no conflict of interest.
- Do not seek confidential government information, non-public records or privileged access.
- Require written conflict-of-interest declarations.
- Pay for documented expertise, not influence or access.
- Validate every legal claim against public official sources and counsel.
- Never imply government endorsement without written authorization.

## Current AI-assisted team boundary

ChatGPT can assist as product/architecture copilot: inspect repository artifacts, draft specifications, implement bounded changes through connected development tools, review test evidence and prepare release checklists. It is not a human CEO, certified government officer, retained lawyer, security auditor or continuously operating engineering team. It cannot independently recruit employees or promise background work between conversations.

## Beta release team sign-off

- CTO: architecture, code review, production configuration and rollback
- QA: end-to-end test evidence and regression report
- Security/privacy: threat model, privacy notice, retention/deletion and incident plan
- Government-domain advisor: source accuracy and statutory boundaries
- Founder: product scope, user terms, launch decision and public claims
